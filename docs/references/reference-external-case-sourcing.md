# 外部测试用例获取规范

> **定位**：本文档定义 nexus-testing 框架如何从外部来源搜索、评估、集成测试用例。测试设计师（阶段三）和测试工程师（阶段五）引用本文件。

---

## 一、何时需要获取外部 Case

| 场景 | 必要性 | 说明 |
|------|--------|------|
| 安全类产品（Web3 防护、代码扫描器等） | **必须** | 需要覆盖已知攻击向量和 CVE |
| 有已知官方测试套件的产品 | **必须** | 官方测试套件通常覆盖核心功能路径 |
| 测试框架/验证工具 | **建议** | 同类框架的测试方案有参考价值 |
| 通用工具类产品 | **可选** | 可在内部设计无法覆盖时补充 |

## 二、搜索策略

### 2.1 GitHub 搜索

**搜索查询模板**：
```
"{产品名}" test
"{产品名}" test-suite
"{产品名}" e2e
"{产品名}" integration-test
```

**过滤策略**：
- 优先级 1：官方仓库的 `test/`、`__tests__/`、`*.test.*`、`*.spec.*`
- 优先级 2：CI/CD 配置文件（`.github/workflows/`、`.gitlab-ci.yml`）中的测试命令
- 优先级 3：社区维护的测试仓库（star 数 > 10，最近 1 年内有更新）

**关注内容**：
- 测试数据和 fixture 文件
- 测试命令和执行方式
- 边界条件和异常场景
- 断言逻辑（期望值是什么）

### 2.2 ClawHub 搜索

**搜索范围**：
- 同类 Skill 的发布版本
- 标注为 "test" 或 "testing" 类型的 Skill
- 下载量高、评分高的同类产品

**评估重点**：
- 是否附带测试用例或 eval 数据
- 触发条件和断言是否清晰
- 是否有已知缺陷报告

### 2.3 漏洞数据库（安全类产品必查）

| 数据库 | URL | 适用场景 |
|--------|-----|---------|
| CVE / NVD | nvd.nist.gov | 已知漏洞编号和详情 |
| GitHub Advisory | github.com/advisories | 开源项目安全通告 |
| Snyk Vulnerability DB | snyk.io/vuln | 依赖链漏洞 |
| OWASP Testing Guide | owasp.org/www-project-web-security-testing-guide | Web 安全测试方法 |
| SWC Registry (Web3) | swcregistry.io | 智能合约弱点模式 |

### 2.4 行业测试套件

| 产品类型 | 推荐测试套件 |
|---------|------------|
| Web 安全扫描器 | OWASP WSTG 测试用例 |
| 代码分析工具 | CWE 示例代码集合 |
| Web3 安全工具 | SWC Registry 测试用例、Damn Vulnerable DeFi |
| Linter/格式检查器 | 相应语言的 ECMAScript Test262、Python test suite |
| API 测试框架 | OpenAPI Schema Test Suite |

## 三、评估标准（评分卡）

每个外部候选用例按以下 6 维度评分：

| 维度 | 权重 | 0 分 | 1 分 | 2 分 | 3 分 |
|------|------|------|------|------|------|
| **相关性** | 30% | 与被测产品无关 | 部分相关 | 高度相关 | 直接命中核心功能 |
| **断言质量** | 20% | 无断言 | 仅检查不崩溃 | 有基本 pass/fail | 精确匹配预期输出 |
| **时效性** | 15% | > 2 年未更新 | 1-2 年 | 6-12 月 | < 6 个月 |
| **可执行性** | 15% | 无法在当前环境运行 | 需大量改造 | 需少量适配 | 可直接运行 |
| **独特覆盖** | 10% | 与已有用例完全重复 | 大部分重复 | 有新场景 | 覆盖全新维度 |
| **许可证** | 10% | 不兼容（GPL/专有） | 需确认 | Apache-2.0 | MIT / BSD |

**最低采纳分**：加权平均 ≥ **2.0/3.0**

**计算公式**：
```
score = (相关性×0.30 + 断言质量×0.20 + 时效性×0.15 + 可执行性×0.15 + 独特覆盖×0.10 + 许可证×0.10)
```

## 四、集成流程

```
1. 搜索 → 使用策略 2.1-2.4 获取候选
    ↓
2. 评分 → 使用评分卡三维度评估每个候选
    ↓
3. 筛选 → 保留加权平均 ≥ 2.0 的候选
    ↓
4. 编号 → 映射为 EXT-TC-{NN} / EXT-FX-{NN}
    ↓
5. 适配 → 改造为 nexus 执行证明格式（4 字段）
    ↓
6. 执行 → 通过沙箱或真实执行验证
    ↓
7. 记录 → 在 TEST-DESIGN.md 中填写来源追溯表
```

### 4.1 适配规则

外部用例适配时必须：
- 统一为 TC 格式：用例编号 / 模块 / 优先级 / 类型 / 步骤 / 预期结果
- 统一执行证明格式：执行动作 / 实际输入 / 实际输出 / 判定
- 保留原始断言逻辑（不得简化）
- 标注原始来源（URL + 原始 ID）

### 4.2 编号约定

| 编号 | 范围 | 说明 |
|------|------|------|
| TC-{NN} | 内部设计的用例 | 测试设计师原创 |
| EXT-TC-{NN} | 外部获取的用例 | 独立编号序列 |
| FX-{NN} | 内部设计的夹具 | 测试设计师原创 |
| EXT-FX-{NN} | 外部获取的夹具 | 独立编号序列 |
| META-TC-{NN} | 元测试用例 | 测试框架专用 |

外部编号不占用内部编号序列，可独立递增。

## 五、来源追溯

TEST-DESIGN.md 中引用外部用例时，必须包含来源追溯表：

```markdown
## 外部用例来源追溯

| Case ID | Source | URL | License | Adapted From | Adaptation Notes | Score |
|---------|--------|-----|---------|-------------|-----------------|-------|
| EXT-TC-01 | GitHub goplus/agentguard | https://github.com/... | MIT | test/scan.test.ts L45-60 | 适配为 CLI 调用模式 | 2.6 |
| EXT-TC-02 | SWC Registry | https://swcregistry.io/... | MIT | SWC-101 测试用例 | 改造为 Skill 触发测试 | 2.3 |
```

**追溯表字段说明**：
- **Source**：来源标识（GitHub 仓库/漏洞库/行业套件等）
- **URL**：原始资源的完整链接
- **License**：原始资源的许可证
- **Adapted From**：原始资源中的具体位置（文件路径/用例 ID/行号）
- **Adaptation Notes**：适配改造说明（如何从原始格式转换为 nexus 格式）
- **Score**：评估评分卡的加权得分

## 六、质量门禁

外部用例与内部用例接受相同的质量标准：

| 检查项 | 标准 |
|--------|------|
| 执行证明合规 | 必须包含 4 字段（执行动作/实际输入/实际输出/判定） |
| 降级标注 | 如降级执行，必须标注降级级别 |
| 来源可追溯 | 来源追溯表完整填写 |
| 许可证合规 | 不得引入与项目许可证不兼容的外部资源 |
| evidence-collector 审计 | EXT-TC 用例接受与 TC 用例相同的审计检查 |

**不合规的外部用例处理方式**与内部用例相同（不计入执行率、打回补充）。
