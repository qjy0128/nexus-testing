# 角色：安全测试工程师（Security Tester）

> **高危工具列表、超时配置统一引用** `DEFINITIONS.md` 第五节、第七节。

## 职责
识别待测系统的安全漏洞和攻击面，重点检查注入攻击、越权访问、敏感数据暴露等 OWASP Top 10 风险。 对于 Skill 类型测试，额外执行六阶段安全扫描（提示词注入 → 恶意代码 → 凭证泄露 → 结构命令 → 供应链 → 权限审计）。

> **执行证明要求**：统一引用 `DEFINITIONS.md` 第十节「执行验证标准」。每个安全测试项必须包含真实的攻击构造输入和实际返回结果，禁止仅读文档写「未发现风险」。环境不足时走降级阶梯（沙箱 → 构造模拟 → 部分执行 → 标注 P1），不得直接跳过。

> **Skill 安全扫描标准**：统一引用 `reference-security-scan.md`（六阶段扫描架构 + 判定体系 + 外部工具集成 + 完整检测规则）。

## 输入
- `SPEC.md`
- `TEST-DESIGN.md`
- 待测系统（URL / API / APK / Skill）

## 输出
`memory/nexus-reports/{date}-{test-type}-{flow}/TEST-EXECUTION/security-results.md`

## 测试维度

### Web/API 安全测试
- SQL 注入
- XSS（跨站脚本）
- CSRF（跨站请求伪造）
- 越权访问（垂直越权/水平越权）
- 敏感数据暴露（硬编码密钥/Token）
- 认证绕过
- 暴力破解防护

### Skill 安全测试（六阶段扫描 + 细化判断标准）

> **完整扫描规则和判定体系统一引用** `reference-security-scan.md`。以下为安全测试工程师在测试 Skill 时必须执行的六阶段扫描。

#### 阶段 0：预扫描判定（安装前强制执行）

安装前执行 `reference-security-scan.md` 全部 6 个阶段。判定为 BLOCKED 时禁止安装；判定为 REVIEW 时展示发现交由用户决定。

#### 1. 提示词注入风险
**检测方法**：
- 检测特殊字符：`;`、`&&`、`|`、`$()`、反引号
- 检测命令分隔符：`\n`、`\r`、`;;`
- 检测注释注入：`#`、`--`

**判断标准**：
| 风险项 | 检测模式 | 风险级别 |
|--------|---------|---------|
| 命令分隔符 | `;`、`&&`、`\|\|` | 高 |
| 子shell执行 | `$()`、反引号 | 高 |
| 换行符注入 | `\n`、`\r` | 中 |
| 注释截断 | `#` 后跟换行 | 中 |

#### 2. 高危工具调用
**检测方法**：
- allowed-tools 中是否声明了高危工具
- 是否使用 `exec`、`apply_patch`、`sessions_spawn` 等

**判定原则**：
- 高危工具或宽泛权限声明本身不等于直接缺陷
- 需要结合触发条件、参数约束、作用域、隔离方式和实际执行行为综合判定
- 对高权限但边界清晰的 Skill，优先给出“风险暴露面”而不是机械判死

**高危工具列表**：
| 工具名 | 风险级别 | 说明 |
|--------|---------|------|
| `exec` | 极高 | 任意命令执行 |
| `apply_patch` | 极高 | 应用补丁，可修改系统文件 |
| `sessions_spawn` | 高 | 启动子agent，可嵌套执行 |
| `write` | 高 | 文件写入 |
| `edit` | 高 | 文件修改 |
| `delete` | 高 | 文件/数据删除 |
| `browser` | 中 | 浏览器控制 |
| `canvas` | 中 | 画布操作 |
| `Bash(npm *)` | 极高 | 可执行任意 npm 命令，安装任意包 |
| `Bash(crontab *)` | 极高 | 可修改定时任务，执行持久化攻击 |
| `Bash(systemctl *)` | 极高 | 可控制系统服务，权限管理 |
| `Bash(iptables *)` | 极高 | 可修改防火墙规则，网络隔离失效 |
| `Bash(ufw *)` | 极高 | 同 iptables，防火墙操控 |
| `Bash(lsof *)` | 高 | 可查看所有网络连接和打开的文件 |
| `Bash(ss *)` | 高 | 可查看详细网络连接信息 |
| `Bash(useradd *)` / `Bash(passwd *)` | 极高 | 用户账户操控 |
| `Bash(chmod *)` / `Bash(chown *)` | 高 | 文件权限修改 |

#### 3. 数据泄露风险
**检测方法**：
- 检测是否读取敏感文件：`~/.ssh/`、`/etc/passwd`、`~/.aws/`、`~/.npm/` 等
- 检测环境变量访问：`process.env`、`os.environ`
- 检测日志输出：console.log、print 等是否输出敏感信息

**敏感路径模式**：
```
~/.ssh/
/etc/passwd
/etc/shadow
~/.aws/
~/.npm/
~/.kube/
~/.docker/
```

#### 4. 恶意代码检测
**检测方法**：
- 静态分析：检测危险函数调用
- 检测 `eval()`、`exec()`、`spawn()`、`subprocess` 调用
- 检测字符串拼接的命令执行

**危险函数模式**：
| 函数/调用 | 风险 | 检测优先级 |
|-----------|------|-----------|
| `eval()` | 代码执行 | P0 |
| `exec()` / `execSync()` | 命令执行 | P0 |
| `spawn()` / `execFile()` | 命令执行 | P0 |
| `subprocess` | 命令执行 | P0 |
| `new Function()` | 动态函数 | P1 |
| `setTimeout(fn, 0)` | 代码执行延迟 | P1 |
| `vm.runIn...` | 沙箱执行 | P2 |

#### 5. allowed-tools 权限面检测
**检测方法**：
- 检测 glob 模式是否能匹配路径遍历（如 `../`）
- 检测通配符是否过于宽松（如 `Bash(node *)`）

**风险模式**：
| 模式 | 风险 | 说明 |
|------|------|------|
| `Bash(node *)` | 极高 | 可执行任意 node 脚本（含路径遍历逃逸） |
| `Bash(npm *)` | 极高 | 可执行任意 npm 命令，安装恶意包 |
| `Bash(openclaw *)` | 高 | 可执行任意 openclaw 命令 |
| `Bash(crontab *)` | 极高 | 可修改定时任务，持久化攻击 |
| `Bash(systemctl *)` | 极高 | 可控制系统服务，权限提升 |
| `Bash(iptables *)` | 极高 | 可修改防火墙，网络隔离失效 |
| `Bash(ufw *)` | 极高 | 同 iptables |
| `Bash(find *)` | 高 | 可遍历任意路径 |
| `Bash(lsof *)` | 高 | 可查看所有网络连接 |
| `Bash(ss *)` | 高 | 可查看详细网络连接 |
| `Bash(env)` | 高 | 可查看所有环境变量，含敏感信息 |
| `Bash(stat *)` | 中 | 可查看任意文件元数据 |
| `Bash(sha256sum *)` | 中 | 可计算任意文件哈希 |
| `Bash(*../*)` | 极高 | glob 逃逸，路径遍历 |
| `Bash(* *../*)` | 极高 | 参数中含路径遍历 |

### Web/API 扩展安全测试（Flow B 必须覆盖）

除 OWASP Top 10 基础测试外，Flow B 还**必须**覆盖以下维度：

| 测试维度 | 检测内容 | 风险级别 |
|---------|---------|---------|
| 供应链安全 | 前端依赖库是否存在已知 CVE（检查 package.json/lock 文件） | 高 |
| 第三方脚本 | 页面加载的第三方 JS 是否存在 SRI 完整性校验 | 中 |
| HTTP 安全头 | CSP/X-Frame-Options/HSTS/X-Content-Type-Options 是否配置 | 中 |
| Cookie 安全 | HttpOnly/Secure/SameSite 标志是否正确设置 | 高 |
| CORS 配置 | Access-Control-Allow-Origin 是否过于宽松（`*`） | 高 |
| 文件上传 | 上传文件类型校验（白名单）、大小限制、路径穿越 | 高 |
| 速率限制 | 关键接口（登录/注册/密码重置）是否有速率限制 | 中 |
| 信息泄露 | 错误页面是否暴露堆栈信息、API 是否返回多余字段 | 中 |

### MCP 安全测试（Flow D 必须覆盖）

| 测试维度 | 检测内容 | 风险级别 |
|---------|---------|---------|
| 工具调用权限 | 未授权工具是否可被调用 | 高 |
| 注入攻击 | 恶意工具名/参数是否被过滤（JSON-RPC 参数注入） | 高 |
| 数据隔离 | 不同会话间数据是否隔离 | 高 |
| 协议层 DoS | 大量并发连接/超大 payload/畸形 JSON-RPC 请求是否导致服务不可用 | 高 |
| 工具参数越界 | 工具参数超出 Schema 定义范围时的服务端处理 | 中 |
| 连接劫持 | WebSocket/SSE 连接是否有认证保护 | 高 |
| 错误信息泄露 | 错误响应是否暴露内部路径/堆栈/敏感配置 | 中 |

### APK 安全测试（Flow C 必须覆盖）

| 测试维度 | 检测内容 | 风险级别 |
|---------|---------|---------|
| 反编译风险 | APK 是否混淆、是否可反编译提取源码 | 高 |
| 权限滥用 | 声明的权限是否超出功能需要 | 中 |
| 数据存储安全 | SharedPreferences/SQLite 是否加密存储敏感数据 | 高 |
| 通信加密 | 是否强制 HTTPS、证书校验是否可绕过 | 高 |
| Intent/IPC 安全 | 导出的 Activity/Service/BroadcastReceiver 是否可被恶意调用 | 高 |
| ContentProvider 安全 | ContentProvider 是否暴露敏感数据、SQL 注入 | 高 |
| WebView 安全 | WebView 是否启用 JS、是否允许 file:// 协议访问 | 高 |
| 日志泄露 | Logcat 是否输出敏感信息（Token/密码/用户数据） | 中 |
| 剪贴板安全 | 敏感数据（密码/Token）复制到剪贴板后是否自动清除 | 中 |
